# 文章书写规范

本页定义全站 Markdown 文章的统一格式。新增文章请逐条对照，规范用于保证结构长期可维护（spec 5）。

## 1. 必填 frontmatter

每篇文章头部必须包含以下四项，缺一不可：

```yaml
---
title: 文章标题
date: 2026-10-07
tags:
  - 标签一
  - 标签二
category: 01-计算机基础
---
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | 字符串 | 与正文一级标题保持一致 |
| `date` | `YYYY-MM-DD` | 首次发布日期，不随修改变动 |
| `tags` | 字符串数组 | 2–5 个，用于检索归类 |
| `category` | 字符串 | 所属分类，与目录名一致（如 `01-计算机基础`） |

## 2. 标题层级规则

- 正文只能有一个一级标题（`#`），且置于 frontmatter 之后。
- 层级必须连续，禁止跳级：`#` → `##` → `###`，不得从 `#` 直接跳到 `###`。
- 同一篇文章内不重复使用相同标题文本，避免锚点冲突。

## 3. 代码块规范

- 所有围栏代码块必须标注语言，禁止无标识代码块：

````text
```bash
sudo tcpdump -i eth0
```
````

- 行号由站点统一开启，单块如需关闭用 `:no-line-numbers`。
- 终端输入与输出建议合并放在 `bash` 块中，用注释区分。

## 4. 文末「更新日志」

每篇文章结尾必须有二级标题「更新日志」，用表格记录，最新一行在下：

```markdown
## 更新日志

| 日期 | 说明 |
| --- | --- |
| 2026-10-07 | 初稿 |
```

## 5. 图片引用

- 图片统一放在 `docs/public/images/`（spec 6.1）。
- 正文以站内绝对路径引用：`![描述](/images/xxx.png)`。
- 描述文字必须填写，不得留空。

## 6. 可选增强

以下能力按需使用，均已在站点配置中启用：

- **公式**：`$行内$` 与 `$$块级$$`（KaTeX 渲染）。
- **流程图**：` ```mermaid ` 代码块。
- **提示容器**：`::: tip` / `::: info` / `::: warning` / `::: danger` / `::: details`，默认标签为中文。
